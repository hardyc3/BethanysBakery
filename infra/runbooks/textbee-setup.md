# TextBee setup (SMS OTP, STOP/START webhook, optional admin SMS)

Prerequisites
- TextBee account, gateway device online, API key and device ID available.
- `TEXTBEE_BASE_URL` must use HTTPS in production.
- Webhook secret generated by operator and stored in env + app config.
- Optional `ADMIN_ALERT_PHONE` receives new-order admin SMS. Full phone numbers
  are masked in API responses and logs.

Console / DNS
1. TextBee dashboard → Gateway device → copy device ID and API key.
2. Webhooks → add `https://bakery.cherry-home.com/api/v1/webhooks/textbee` for inbound SMS events.
3. Set the shared secret; inbound signature header is `X-Textbee-Signature: sha256=<hex HMAC>`.
4. The webhook path is unauthenticated at the edge (geo rule exempt) and verified
   by HMAC signature at the origin.

Set env (single LXC)
```bash
cd /opt/bethanys-bakery
ENV_FILE=/opt/bethanys-bakery/.env
read -rsp 'TextBee API key: ' TEXTBEE_API_KEY; echo
read -rsp 'TextBee webhook secret: ' TEXTBEE_WEBHOOK_SECRET; echo
for pair in "TEXTBEE_API_KEY:$TEXTBEE_API_KEY" "TEXTBEE_WEBHOOK_SECRET:$TEXTBEE_WEBHOOK_SECRET"; do
  key=${pair%%:*}; val=${pair#*:}; esc=$(printf '%s' "$val" | sed 's/[&|\\]/\\&/g')
  sed -i "s|^$key=.*|$key=$esc|" "$ENV_FILE"
done
unset TEXTBEE_API_KEY TEXTBEE_WEBHOOK_SECRET
# Edit with a mode-600 editor: TEXTBEE_BASE_URL=https://api.textbee.dev/api/v1
#                              TEXTBEE_DEVICE_ID=<device-id>
#                              ADMIN_ALERT_PHONE=+15551234567 (optional)
git pull --ff-only
docker compose -f infra/compose.prod.yml --env-file "$ENV_FILE" up -d --build
sh infra/scripts/status.sh
```

Verification
```bash
# 1. Real OTP path (run from a US network).
curl -sS -X POST https://bakery.cherry-home.com/api/v1/auth/otp/request \
  -H 'Content-Type: application/json' \
  --data '{"channel":"SMS","destination":"+15551234567"}'    # 202

# 2. Signed webhook (STOP opt-out) — reaches origin despite the geo rule.
set -a; . "$ENV_FILE"; set +a
BODY='{"from":"+15551234567","message":"STOP","providerMessageId":"test-1","receivedAt":"2026-01-01T00:00:00Z"}'
SIG=$(printf '%s' "$BODY" | openssl dgst -sha256 -hmac "$TEXTBEE_WEBHOOK_SECRET" -hex | awk '{print $NF}')
curl -sS -o /dev/null -w '%{http_code}\n' -X POST \
  https://bakery.cherry-home.com/api/v1/webhooks/textbee \
  -H 'Content-Type: application/json' -H "X-Textbee-Signature: sha256=$SIG" --data "$BODY"   # 204
curl -sS -o /dev/null -w '%{http_code}\n' -X POST \
  https://bakery.cherry-home.com/api/v1/webhooks/textbee \
  -H 'Content-Type: application/json' -H 'X-Textbee-Signature: bad' --data "$BODY"           # 401
```
Check the customer record shows `smsOptOutAt`, then send `START` with a fresh
signature to confirm re-consent. Trigger a new order with `ADMIN_ALERT_PHONE`
set and confirm an SMS is queued with its own idempotency key.

Rollback
- Restore previous env values and redeploy; remove the webhook in TextBee if the
  secret leaked (then rotate secret). No DB changes.

Notify
- Owner + ops on-call after first OTP and webhook verification; security owner for secret rotation.
